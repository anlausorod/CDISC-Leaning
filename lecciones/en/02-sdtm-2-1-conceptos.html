Model concepts and terms

SDTM is a general framework for organizing the information collected in a study and submitted to regulatory authorities. The whole model rests on three ideas: observation, variable and domain.

The three core ideas

An SDTM dataset is a flat file, like a spreadsheet. Each concept of the model has an exact place in that table.

Observation= a rowA discrete piece of information collected during the study.
Variable= a columnA named value that describes the observation. Every variable has a Role.
Domain= a datasetLogically related observations that share a topic, for example adverse events.

The 5 roles of a variable

The Role states what kind of information the variable conveys about each observation and how it can be used. Each role answers a different question.

Identifier

Whose record is it, and which one?Identifies the study, the subject (a person, an animal or a group), the domain and the sequence number of the record.USUBJID DOMAIN --SEQ

Topic

What is the observation about?Specifies the focus of the observation, such as the name of a lab test or the adverse event term.--TERM --TRT --TESTCD

Timing

When did it happen?Describes the timing of the observation, such as start date and end date.AESTDY

Qualifier

What else do we know about it?Text or numeric values that describe the results or additional traits, such as units or descriptive adjectives. It is divided into 5 subclasses.AESEV --ORRESU

Rule

Under what condition does it start, end or repeat?Expresses an algorithm or executable method to define start, end or looping conditions. Used only in the Trial Design model.

The domain code and its four uses

Each domain is identified by a unique two-character code that must be used consistently throughout the submission. That code appears in four places. Switch domains to see it.

Domain:
1. Dataset name
2. Value of the DOMAIN variable
3. Prefix of most variable names
4. Value of RDOMAIN in relationship tables
Domain names are common examples from the implementation guides.

Metadata: the define.xml document

Every dataset is submitted with a data definition document called “define”, which describes its variables. Define.xml uses seven attributes per variable. Here they are applied to AETERM.

AttributeExampleWhat the model requires
NameAETERMUp to 8 characters, for compatibility with the SAS Transport format.
LabelReported Term for the Adverse EventDescriptive, up to 40 characters and unique within the dataset.
TypeCharCharacter or numeric only (a SAS v5 transport limitation).
Controlled terms or format—The controlled terminology for the values, or their display format.
OriginCRFWhere the variable comes from. Uses CDISC controlled terminology.
RoleTopicHow the variable is used: Identifier, Topic, Timing or one of the five qualifiers.
CommentsFree textAnything the sponsor needs to explain to the agency about the variable or its data.

Raw and derived data

Variables hold raw values, as captured by whoever provided the data, and derived values, such as a conversion to standard units or a calculated age.

What SDTM fixes and what comes later

SDTM defines the name, label, role and type of the standard variables. More descriptive data types (integer, float, date, datetime) are expected in the future, once the SAS v5 requirement changes.

Rules for the sponsor

When preparing a submission, the sponsor has very limited latitude over the variables.

  • AllowedOmit variables defined as permissible in the implementation guide, and their description in define.xml, as long as no data were collected for them.
  • Not allowedAdd new sponsor-defined variables.
  • Not allowedRename existing variables or modify them for a different use.
  • CheckThe relevant implementation guide states which variables are required, expected or permissible in each domain.
