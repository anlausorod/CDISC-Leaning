2.1

Observations and variables

The SDTM is built around the observations collected about the subjects in a study. Each observation is described by a series of variables and corresponds to a row in a dataset or table.

Observation= a rowA piece of data collected about a study subject.
Variable= a columnDescribes the observation. Every variable is classified by its Role.

Variable roles

The Role states what kind of information the variable conveys about each observation and how it can be used. There are four major roles, plus a fifth one, Rule, introduced in V3.1.

Identifier

Whose record is it, and which one?Identifies the study, the subject, the domain and the sequence number of the record.STUDYID USUBJID DOMAIN --SEQ

Topic

What is it about?Specifies the focus of the observation, such as the name of a lab test.--TRT --TERM --TESTCD

Timing

When did it happen?Describes the timing of the observation, such as start date and end date.--STDTC --ENDTC --STDY

Qualifier

What else do we know?Text or numeric values that describe the results or additional traits, such as units or descriptive adjectives.--ORRES --SEV --ORRESU

Rule

When does it start, end or repeat?Expresses an algorithm or executable method to define start, end or looping conditions in the Trial Design model.

2.2

Datasets and domains

A domain is a collection of logically related observations with a common topic. Each domain is normally submitted as one dataset: a flat file in which each row is an observation and each column a variable.

The DOMAIN code

Each dataset is distinguished by a unique two-character code that should be used consistently throughout the submission. Switch domains to see its three uses.

Domain:
1. Dataset name
2. Value of the DOMAIN variable
3. Prefix of most variable names

Metadata: the “Define” document

Each dataset comes with a data definition document, “Define” (define.xml), that describes its variables using seven attributes. Here they are applied to AETERM:

AttributeExampleWhat the guide says
NameAETERMUp to 8 characters, for compatibility with SAS Transport.

CommentsFree textAny relevant information about the variable or its data.

Raw and derived data

Variables hold values as originally collected and derived values, such as a conversion to standard units or an average.

SDTM vs. the guide

The SDTM only fixes name, label and type. The guide's domain models (sections 5 and 6) add controlled terms, origin and usage notes.

2.4

The general domain classes

All other observations are divided among three general classes. Pick one to see what it captures.

In most cases the class follows easily from the topic. Findings is often the best choice for measurements or responses to questions. When it is not clear, the choice is based on the scientific intent of the protocol, the analysis plan or the data structure (Appendix 10.6).

Three common rules

  • IdentifiersThe same set of identifier variables applies to all domains based on the general classes.
  • TimingAny valid timing variable may be used in any dataset, but consistently across all domains.
  • QualifiersAny additional qualifier from the same general class may be added to a domain model.

What the sponsor may and may not do

  • Only collectedSubmit only the domains whose data were actually collected in the study.
  • AllowedAdd relevant timing variables and qualifiers from the same general class, and drop variables from the model (with their description in Define).
  • Not allowedAdd any other new variables, rename existing ones or use them for a different purpose.
  • SUPPQUALData that do not fit the model's variables go into the Supplemental Qualifiers dataset (Section 8.4).
  • ConsistencyAny collected data in an analysis dataset must also appear in a tabulation dataset.

The V3.x paradigm is very different from earlier versions: data once modeled horizontally in a single record are now often converted into multiple records.
